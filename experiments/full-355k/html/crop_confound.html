Does cropping explain the detectors' scores? — full AI-GenBench set¶

The question in plain words: every image is scored on a 200×200 pixel crop, never the full picture. For a small image, that is almost the whole image; for a big photo, a tiny slice. Real photos here tend to be larger than fakes, so "how much of the picture survives the crop" differs between the classes. If a detector could key off that instead of content, its scores would be worthless as evidence.

Four steps:

  1. Could crop fraction by itself, with no pixels at all, tell real from fake? (Is the shortcut available?)
  2. Do the detectors' scores move with it among real photos?
  3. Remove the shortcut (compare only images cropped by a similar amount) and see whether the detectors still separate real from fake.
  4. Look at which real photos cause trouble.

No detector is re-run — this reads the 355,638-image score table and the crop geometry recorded in manifest.csv.

def auroc(score, label):
    '''Rank-based AUROC; no sklearn in this env. score first, label second -- same
    convention as merge_scores.ipynb.'''
    r = pd.Series(score).rank()
    npos, nneg = (label == 1).sum(), (label == 0).sum()
    if npos == 0 or nneg == 0:
        return np.nan
    return (r[label == 1].sum() - npos * (npos + 1) / 2) / (npos * nneg)

def spearman(a, b):
    '''Rank correlation; no scipy in this env.'''
    a, b = pd.Series(a).rank(), pd.Series(b).rank()
    a, b = a - a.mean(), b - b.mean()
    return float((a * b).sum() / np.sqrt((a * a).sum() * (b * b).sum()))

Step 1 — is the shortcut even available?¶

If we throw away every pixel and score each image by frac alone (nothing but "how much of the original photo survived the crop"), how well would that already separate real from fake?

Brief. Yes, the shortcut exists: crop fraction alone gives AUROC 0.78 — better than AEROBLADE (0.59) and close to cnndetection (0.79) on actual pixels. 44% of fakes are small enough to survive the crop whole, versus 1.4% of real photos. (Local sample: 0.85.) So we have to rule out that the detectors use it.

Step 2 — do the detectors actually use it?¶

Real photos only. Fakes tend to be uncropped (large frac), so a detector exploiting the shortcut would score large-frac images as more fake, i.e. a positive correlation between log frac and score. A negative correlation means the opposite: the harder a real photo is cropped, the more fake it looks — not what the shortcut predicts.

Brief. Almost no relationship. cnndetection (−0.07) and dmid_latent (+0.02) are flat; univfd and dmid_progan are weakly backwards (−0.13, −0.12); only AEROBLADE leans the shortcut way (+0.20), and modestly.

On the local sample, all four classifiers were strongly backwards (−0.36 to −0.57). That difference comes from RAISE: there it was a third of the real photos and is both the most-cropped and the most fake-looking source. Here RAISE is 0.6% of real photos and the correlation mostly disappears — so the local "harder crop → looks fake" effect was a RAISE effect, not a crop effect.

Step 3 — the acid test: remove the shortcut and see what's left¶

Restrict to the band of frac where real and fake photos overlap a lot (so "how much was cropped" stops being a useful guess on its own), and recompute AUROC there. If the detectors were relying on the shortcut, taking it away should tank their AUROC. If they're reading actual content, it should hold up — or even improve, since Step 2 showed the shortcut was working against real photos.

Step 4 — which real photos cause the trouble?¶

RAISE: camera-raw, very high resolution (2000×3008 to 4928×3264), no history of web JPEG re-encoding — the closest thing in this set to archival material. Below, a threshold is set so each detector falsely flags 5% of COCO, then applied to the other sources.

Brief. Same threshold, very different false-alarm rates:

  • LAION: 8–10% on the three GAN-leaning classifiers, but 31% on dmid_latent and 46% on AEROBLADE.

These rates match the local sample within ~4 points (except dmid_latent, 44% → 58%). This is the most stable result so far: the detectors read "unusual capture/processing pipeline" as a generation artifact — the archival-domain-gap problem.

Brief: summary in plain words¶

  • The shortcut exists (crop fraction alone: AUROC 0.78), but the detectors are not using it: scores barely move with crop fraction among real photos, and removing the shortcut leaves every detector's AUROC about the same or higher.
  • The real problem is RAISE. At a threshold with 5% false alarms on COCO, 20–58% of genuine camera-raw photos are flagged as fake. This held from 612 to 355,638 images.

Caveats¶

  • Correlational. It shows the panel isn't exploiting crop geometry here, not that no detector ever could.
  • RAISE is the only high-resolution source and only 1,000 images, so "RAISE-ness" and "heavily cropped" still cannot be fully separated with this data.
  • AUROC is used only as a diagnostic; Cllr/DET/Tippett are elsewhere.

Suggested next step (~20 min, optional)¶

Take a handful of RAISE images, crop the same image at several frac values, and rescore. Same content, only crop fraction changes — that turns this into a causal test.
