Does detector score track release date within the diffusion family? — full AI-GenBench set¶

merge_scores.ipynb §6 fitted one trend across all families, which confounds release date with family (GANs early, diffusion late). This notebook holds family fixed — diffusion only — and replaces the eyeballed slope with a rank correlation and a p-value.

What is being asked¶

Sixteen diffusion generators, released between 2020-06 and 2024-08. For each one, the median score the panel gives its images. Does that median move monotonically with release date?

  • R (Spearman's rho) — do the two move together in rank order? 0 = no relationship, −1 = newest generators get the lowest scores. Rank-based, so no straight-line assumption and one outlying generator cannot drive it.
  • p — how often a correlation at least this strong appears when release dates are shuffled at random. Small p = hard to explain as coincidence.

Why it matters. Resolving time within a family requires score to carry temporal signal once family is fixed. If R is ~0, a family has to be treated as one bucket and time resolved only between families.

The unit of analysis: one row per generator (n = 16)¶

Not one row per image (n = 80,000). All 5,000 Stable Diffusion 1.5 images share one release date; counting them separately adds no temporal information and shrinks the p-value for nothing. §5 shows how badly that inflates things.

n = 16 is small no matter how many images each generator has — §4 says which effect sizes this test can detect at all.

3. Spearman R and a permutation p-value¶

Spearman's rho is Pearson's correlation on ranks. The p-value comes from shuffling the release dates 200,000 times and counting how often chance alone gives a correlation this strong — no distributional assumption, with a floor of ~5e-6.

The null permutes each detector's own median-ranks, so any ties are carried into it. (On the local sample AEROBLADE had tied medians; with 5,000 images per generator there are none — the ties column is 0 throughout.)

Five detectors means five tests, so p-values are Holm-corrected — without it, testing five things at α = 0.05 gives roughly a 1-in-4 chance of at least one false "significant".

def rankdata(a):
    """Average ranks; ties share their mean rank (scipy's 'average' method)."""
    a = np.asarray(a, float)
    r = np.empty(len(a), float)
    r[a.argsort()] = np.arange(1, len(a) + 1)
    for v in np.unique(a[pd.Series(a).duplicated(keep=False).to_numpy()]):
        m = a == v
        r[m] = r[m].mean()
    return r


def spearman_r(u, v):
    return float(np.corrcoef(rankdata(u), rankdata(v))[0, 1])


def perm_null(ranks_x, ranks_y, n_perm=N_PERM, seed=SEED):
    """Rho under H0: x-ranks fixed, y-ranks shuffled.

    Permuting the observed y-ranks rather than 1..n keeps any tie structure intact,
    which matters wherever two generators share a median.
    """
    P = np.argsort(np.random.default_rng(seed).random((n_perm, len(ranks_x))), axis=1)
    a = ranks_x - ranks_x.mean()
    B = ranks_y[P] - ranks_y.mean()
    return (B @ a) / np.sqrt((a @ a) * (B ** 2).sum(axis=1))


def perm_p(rho, null):
    """Two-sided, +1-corrected so a p-value is never reported as exactly zero."""
    return (np.sum(np.abs(null) >= abs(rho) - 1e-12) + 1) / (len(null) + 1)


def holm(pvals):
    p, m = np.asarray(pvals, float), len(pvals)
    adj, run = np.empty(m), 0.0
    for k, i in enumerate(p.argsort()):
        run = max(run, (m - k) * p[i])
        adj[i] = min(run, 1.0)
    return adj

rx      = rankdata(x)
Draw    = M[(M.label == 1) & (M.generator_family == "diffusion")]
rows, nulls = [], {}

for d in DETECTORS:
    # the sigma rescaling is monotone, so raw and sigma scores must give identical rho
    raw = Draw.groupby("generator")[d].median().reindex(g.generator).to_numpy()
    assert abs(spearman_r(x, raw) - spearman_r(x, g[d])) < 1e-12, f"{d}: rho not scale-invariant"

    ry        = rankdata(g[d].to_numpy())
    nulls[d]  = perm_null(rx, ry)
    r         = spearman_r(x, g[d])
    rows.append({"detector": zcols[d], "R": r, "ties": int(g[d].duplicated().sum()),
                 "p_perm": perm_p(r, nulls[d])})

R = pd.DataFrame(rows)
R["p_holm"]  = holm(R.p_perm)
R["verdict"] = np.where(R.p_holm < 0.05, "significant", "not distinguishable from chance")

print(f"permutation null: {N_PERM:,} shuffles per detector, p floor {1/(N_PERM+1):.1e}\n")
print(R.assign(R=R.R.round(3),
               p_perm=R.p_perm.map("{:.2g}".format),
               p_holm=R.p_holm.map("{:.2g}".format)).to_string(index=False))

4. Sensitivity: what could this test have detected?¶

A non-significant result at n = 16 is ambiguous — it could mean "no temporal signal" or "there is one but 16 points cannot see it." Distinguishing those is not optional, and the permutation null answers it directly: it is the distribution of R when release date carries no information, so its 95th percentile is the smallest |R| this design can call significant.

Below that value, a real trend and no trend are indistinguishable here. Any detector whose R is inside the gray band should be read as "this experiment cannot tell," not as "no effect."

5. Why the per-image version is not the answer¶

The same test with one row per image. Nothing new is measured — every image inherits its generator's date — but n goes from 16 to 80,000 and the p-values collapse.

This is pseudo-replication, the same failure CLAUDE.md flags for the aggregator: excess temporal granularity biases crossings earlier than warranted — the dangerous direction. Reported only so the inflation is on the record.

Brief: what this settles, and what it does not¶

detector R p Holm
univfd −0.785 0.00063 0.003 significant
dmid_progan −0.30 0.25 1 cannot tell
cnndetection −0.17 0.52 1 cannot tell
aeroblade −0.09 0.73 1 cannot tell
dmid_latent +0.14 0.60 1 cannot tell
  • Only UnivFD gets clearly worse on newer diffusion generators (R = −0.785, still p = 0.003 after Holm). The frozen-CLIP probe was the member expected to generalise best. Stronger than on the local sample (−0.67, Holm 0.03), because 5,000-image medians are far less noisy than 17-image ones.
  • The other four are "cannot tell", not "no effect". |R| must exceed 0.50 for p < 0.05 and 0.64 to survive Holm. Those thresholds depend only on having 16 generators, so more images will not change this — more generators will (e.g. post-Aug-2024 models).
  • dmid_latent points the other way (+0.14, n.s.), directionally consistent with it being the latent-diffusion-trained checkpoint. A hypothesis, not a finding.
  • Consequence for the architecture: panel members age at different rates, so the calibration layer cannot treat detectors as exchangeable over time.
  • §5, the trap: counted per image, four detectors hit the p floor (5e-5) — including dmid_latent's wrong-direction +0.15 — and AEROBLADE gets p = 0.0004 at R = −0.012. That is why the generator stays the unit of analysis.

Caveats:

  • UnivFD's trend leans on three late generators: DeepFloyd IF (0.21 σ), DALL-E 3 (0.64) and FLUX 1 Dev (0.20). FLUX 1 Schnell (1.04) does not follow it. Five generators fall in a six-week window (Nov–Dec 2021), and the two FLUX models are a day apart. Shifting a few release dates by months could move R; testing that is a prerequisite for putting −0.785 in the thesis.
  • Date is still confounded with content and native resolution inside the family (a 2020 DDPM sample and a 2024 FLUX sample differ in more than age). The 200×200 crop bounds the resolution part but does not remove it.
  • The local caveat "17-image medians attenuate R" no longer applies at 5,000 per generator.
